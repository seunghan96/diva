  in PREREG_HASHES.txt is the binding record; the stated time was an estimate). (ii) It says the sigma grid was
  {0, .25, .5, 1, 1.5, 2, 3}. WRONG: the dev scripts at hashing time (dev_uncertain_tab.py / dev_uncertain_voi.py, 07:46)
  evaluated sigma in {1, 1.5, 2, 3} against the point specification (sigma = 0); sigma = 1 is the edge of that grid.
  The later leave-one-domain-out analysis (transfer.py, grid sigma in {0, .5, 1, 1.5} x lambda in {1, .75, .5}) selects
  sigma = 1 (an interior value) for every held-out domain. (iii) On SEC binned checks, the code shifts the two extreme
  bins by +/- sigma*z, so the spread between them moves by 2*sigma*z (effective scale 2 sigma relative to binary checks);
  the paper now states this. (iv) Local SHA-256 hashes are not third-party timestamps; they document content, and the
  order of events is reconstructed from file times and logs.
